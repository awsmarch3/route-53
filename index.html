The flow shows how Route 53 handles DNS resolution. Each step has specific roles and the zone file is where your actual DNS records are stored.

📋 Zone File Structure & Request Flow

Zone File: A text file containing DNS records for your domain. When you migrate to Route 53, your zone file is stored in AWS infrastructure but you manage it through console/API.

Sample Zone File for example.com:

; Zone file for example.com $ORIGIN example.com. $TTL 300 ; SOA Record (Start of Authority) @ IN SOA ns-123.awsdns-15.com. admin.example.com. ( 2024081901 ; Serial number 7200 ; Refresh interval 3600 ; Retry interval 1209600 ; Expire time 86400 ) ; Minimum TTL ; Nameserver records @ IN NS ns-123.awsdns-15.com. @ IN NS ns-456.awsdns-20.net. @ IN NS ns-789.awsdns-25.org. @ IN NS ns-012.awsdns-30.co.uk. ; A records (IPv4) @ IN A 1.2.3.4 www IN A 1.2.3.4 api IN A 5.6.7.8 mail IN A 9.10.11.12 ; AAAA records (IPv6) @ IN AAAA 2001:db8::1 www IN AAAA 2001:db8::1 ; CNAME records ftp IN CNAME www.example.com. blog IN CNAME www.example.com. ; MX records @ IN MX 10 mail.example.com. @ IN MX 20 backup-mail.example.com. ; TXT records @ IN TXT "v=spf1 include:_spf.google.com ~all" _dmarc IN TXT "v=DMARC1; p=quarantine; rua=mailto:dmarc@example.com"

🔄 Request Flow to Zone File:

  1. Client Query: Browser asks for www.example.com
  2. Route 53 Receives: Query reaches Route 53 nameservers
  3. Zone File Lookup: Route 53 checks zone file for matching record
  4. Record Matching: Finds "www IN A 1.2.3.4" in zone file
  5. Response Generation: Returns IP address with TTL
  6. Caching: Response cached at multiple levels based on TTL

🛠️ DNS Tools & Commands by Operating System

🪟 Windows Commands

DNS Lookup:

nslookup www.example.com
nslookup www.example.com 8.8.8.8
nslookup -type=MX example.com
nslookup -type=NS example.com

Advanced DNS Query:

Resolve-DnsName www.example.com -Type A
Resolve-DnsName example.com -Type MX

Flush DNS Cache:

ipconfig /flushdns
ipconfig /displaydns

DNS Configuration:

ipconfig /all
netsh interface ip show dns

🐧 Linux Commands

DNS Lookup:

dig www.example.com
dig @8.8.8.8 www.example.com
dig www.example.com +trace
dig example.com MX
dig example.com NS

Alternative Tools:

host www.example.com
nslookup www.example.com

Flush DNS Cache:

sudo systemctl restart systemd-resolved
sudo systemd-resolve --flush-caches
sudo /etc/init.d/nscd restart

DNS Configuration:

cat /etc/resolv.conf
systemd-resolve --status

🍎 macOS Commands

DNS Lookup:

dig www.example.com
dig @8.8.8.8 www.example.com +short
dig www.example.com +trace
host www.example.com

Flush DNS Cache:

sudo dscacheutil -flushcache
sudo killall -HUP mDNSResponder

DNS Configuration:

scutil --dns
networksetup -getdnsservers Wi-Fi

Change DNS Server:

networksetup -setdnsservers Wi-Fi 8.8.8.8 8.8.4.4

🔧 Route 53 Troubleshooting Guide

❌ Domain Not Resolving

Check:
• Nameserver configuration at registrar
• Route 53 hosted zone exists
• DNS records are correct
dig NS example.com
dig www.example.com +trace

🐌 Slow DNS Resolution

Solutions:
• Check TTL values (not too low)
• Verify Route 53 health checks
• Monitor CloudWatch metrics
dig www.example.com +stats

🔄 DNS Propagation Issues

Verify:
• Check multiple DNS servers
• Wait for TTL expiration
• Use online propagation checkers
dig @8.8.8.8 www.example.com
dig @1.1.1.1 www.example.com

⚠️ Route 53 Health Check Failures

Debug:
• Check endpoint accessibility
• Verify security groups/firewall
• Review CloudWatch alarms
aws route53 get-health-check --health-check-id HCID
